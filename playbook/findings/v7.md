# v7 — building from a reference you cannot see

Route `/v7`. Built from a measured spec of [filmhood.in](https://filmhood.in), a Telugu-film
release tracker, on the same 22-title data set as every other drill.

This one started from an instruction — *"I want the website like this, use three js if you
want"* — and the first useful thing that happened was finding out the premise was wrong.

## 1. The reference has no 3D, and the ask for it was the tell

The brief offered Three.js. The reference does not use it, or anything like it:

```
canvases: NONE
libs: none on window
scripts: googletagmanager, /assets/index-BZzrOv7k.js
```

Two things on that page *read* as three-dimensional and neither is. The poster field is 254
absolutely-positioned anchors driven by `matrix(s,0,0,s,tx,ty)`, where the same `s` is
written to `z-index` as `round(s * 1000)` — scale is the depth cue and paint order follows
it for free. The turntable is a `repeating-radial-gradient` at a 3px period for the grooves,
one `conic-gradient` for the sheen, and an arm that rotates 8° on
`cubic-bezier(.3,1.12,.4,1)` — an easing that crosses 1 before settling, so the needle
overshoots and comes back.

**The quality being attributed to WebGL was coming from two gradients and an easing curve.**
Adding Three.js would have added a bundle and subtracted the thing that made it good. This
is worth stating as a general case, because the misread runs one way: *the impression of
depth is cheap to fake and expensive to buy, and viewers reliably guess the expensive
option.*

## 2. Getting the spec without being able to load the page

`filmhood.in` is blocked by this environment's egress proxy, and so is
`image.tmdb.org`. The site was never loaded here, at any point.

What worked was writing an extraction prompt for a browser-side agent that *could* see it,
and demanding measured values rather than description — `getComputedStyle` dumps, a colour
histogram with counts, the `@font-face` src URLs, `document.fonts`, the resource timeline.
The returned spec identified the display face as **Abril Fatface** from the `family=`
parameter on the stylesheet link, confirmed against `document.fonts`, *not* guessed from
the render.

That distinction is the whole reason it was usable. A prose description of a page —
"warm off-white, generous spacing, a bold serif" — cannot be built from. `#F7F7F1`,
`padding: 80px min(20vw, 280px) 0`, and `Abril Fatface 400` can.

**A design reference is a set of measurements. Anything less is a mood board.**

## 3. What was copied, what was refused, and why the refusals matter more

Copied: the single acid-lime accent (`#e6ff41`) on an otherwise achromatic ground; the
fat-face display serif over a variable grotesque; cards that are **bordered rather than
shadowed**, with hover swapping only the border to lime; the infinite ticker; the magnetic
nav link and its travelling pill; and the one full-bleed inverted block that resolves three
thousand pixels of dark listings into a single bright object.

Refused, and each refusal came from a rule this repo had already paid for:

| Refused | Why |
|---|---|
| The 254-anchor poster depth-field | A rAF loop that never idles, the only effect on that page with **no reduced-motion guard**, and `touch-action: none` over an 880×560 band that swallows vertical swipes |
| Thirteen type sizes on the first screen | Six of them crowded into 10.4–13.12px doing near-identical jobs. `v7` has four, declared once |
| `rgba(255,255,255,.6)` card dates over artwork | Alpha on already-muted text — the exact failure `v5` and `v6` both paid for |
| Dark-only, no `prefers-color-scheme` at all | The constitution requires both themes designed |
| **Horizontal strips for the featured week** | See below — this is the interesting one |

### The strip was the v3 mistake in a new costume

Every group on the reference is a free-scrolling horizontal strip, and that is right for
what it holds: *In Theatres*, *Upcoming*, *Trailers* are open-ended categories where seeing
four and scrubbing for more is the whole interaction.

Built that way here, the featured week showed **three of eleven titles**, with eight behind
a horizontal gesture nothing announced. The page exists to answer *what drops this week*,
and it was hiding two thirds of the answer.

This is `v3` again. `v3` copied JustWatch's platform grouping, `v4` and `v5` inherited it,
all three scored best on every instrument, and the whole verdict pass was needed to notice
the page no longer answered its own question. **A reference's container encodes its data's
shape, not yours.** The card craft, palette and type transfer. The container does not.

The featured week is a grid with a column count derived from the group size, so an 11-title
week runs 3+3+3+2 and never strands a card on its own row.

## 4. Seven defects across three screenshot rounds

Same pattern as `v4` and `v6`: **three of the seven were caused by fixes made earlier in the
same session.**

| # | Defect | Origin |
|---|---|---|
| 1 | Chart bars invisible — the whole section captured as an empty 240px box | Original |
| 2 | No-artwork cards rendered the title twice, overlapping itself | Original |
| 3 | Chevrons parked in a gutter this layout spends on the calendar | Original |
| 4 | Calendar badge showed the count where the date belongs | Original |
| 5 | Cards starved to 160px, titles breaking mid-word | **Self-inflicted** — the grid that fixed #3's strip |
| 6 | Calendar 736px wide with 105px cells; next-run poster 1100px tall | **Self-inflicted** — both sized by a grid column that collapses at 900px |
| 7 | Blank white page, every route | **Self-inflicted** — trimming an unused import took `useRef` with it |

### Defect 1: an entrance animation that was load-bearing

The bars had `transform: scaleY(0)` by default and `scaleY(1)` under a class an
IntersectionObserver was supposed to add. The capture harness photographed an empty box. The
underlying layout bug was separate and worse — a percentage height under `align-content: end`
has no definite basis to resolve against, so every bar had already collapsed to its 3px
floor before the transform hid it.

**An entrance must never be what makes content visible.** The fix inverts the default: the
finished chart is the base state, and the class adds a `backwards`-filled animation. If the
observer never fires, the chart is simply correct.

### Defect 7: a green lint on a page that does not render

`pnpm lint` passed. The route was a white screen. oxlint ships with `no-undef` off, so a
component calling a hook it no longer imported was not a lint error — it was a runtime
crash, caught only because the next screenshot came back blank.

A `.oxlintrc.json` now enables `no-undef`, and it was negative-tested by re-deleting the
import before being trusted.

### The chart that became a list

Defect 1's real resolution was not fixing the chart. Three weeks of data running 1, 11, 1
make a 240px section that is ninety per cent empty, with two stub bars beside one giant one.
Fixed, it was still not worth a section.

The counts moved onto the week list as a bar per row. Same information, no new surface, and
the list gained the thing it was missing — you can now see that one week carries eleven
titles and its neighbours carry one each, which is the argument for grouping by week in the
first place.

**A chart that needs a section to itself and has three data points is a table.**

## 5. Two instruments moved underneath the repo

Neither of these is about `v7`. Both are about trusting a number a document recorded months
ago.

**`impeccable`'s rule set has changed.** `PHASE-2.md` and `README.md` both record `v6` as
**0 findings** and `v1` as **28**. Scanned minutes apart, on the same running server, with
today's version:

| | v1 | v4 | v6 | v7 |
|---|---|---|---|---|
| recorded in the repo | 28 | 3 | 0 | — |
| measured today | **13** | 3 | **5** | **0** |

`v6` did not regress; `gpt-thin-border-wide-shadow` did not exist when `v6` was scored. `v1`
did not improve. **A defect count is a reading of one tool at one version, and the only
comparison that means anything is one where every page was scanned in the same run.** The
`v7 = 0` above is worth exactly that much: it is same-run.

**Node and Chromium disagree about dates.** `pnpm verify:v6` reported 25/27 on an untouched
`v6` — the script formatted expected dates with Node's `Intl` and compared them to text
Chromium rendered, and the two ICU versions differ by one comma. Written up in
[`v6.md` §6](v6.md); `verify:v7` formats inside the page from the start.

## 6. What verification `v7` adds

| Command | What it proves |
|---|---|
| `pnpm verify:v7` | 42 render-vs-data checks — the whole week rendered rather than a subset, no orphan row, calendar marks against release dates including multi-day fixtures, week-list counts and standings, `?week=` and `?region=` URLs, the empty state and its way out, the next-run block |
| `pnpm contrast:v7` | 32 computed pairs, both themes, **read from the running page** rather than from a copy of the palette |

Two things there are deliberate departures from `v6`'s scripts.

`contrast:v6` keeps its own hardcoded copy of the palette, so the check and the stylesheet
can drift apart and the suite keeps reporting green on a palette it is no longer testing.
`contrast:v7` reads the tokens out of the rendered page in both colour schemes.

And the card caption sits over poster artwork, which can be any colour — there is no "the
background" to test. It is tested against the worst ground its own scrim can present: the
scrim composited over a pure white poster (`#F5F5F5` on `#3B3B3B`, 10.27:1).

Every check was negative-tested before being believed — the multi-day fixture expansion, the
orphan-row guard, the empty state, and the contrast floor were each deliberately broken and
confirmed to go red. **A check restored to green proves nothing until you have watched it
fail on purpose.**

## 7. The honest gap

**No poster has ever rendered on this page.** `image.tmdb.org` is blocked here, so all
fourteen titles with artwork fall through to the designed no-artwork tile, and every
screenshot in `lab/shots/v7/` shows that state.

For a design whose reference serves 269 posters on its homepage and whose entire chrome is
built to stay achromatic *so the artwork can be the colour*, this is not a small caveat. The
composition, the density, and the contrast of the caption against real artwork are all
unreviewed. What the shots do show is a state that genuinely ships — eight of the
twenty-two titles have `poster: null` in the data, and any reader behind a network that
blocks TMDB sees exactly this.

The load-failure fallback was itself found this way: before it existed, a blocked poster
rendered as a broken-image glyph. Two different absences — no artwork in the data, and
artwork on an unreachable host — now end in the same designed tile, because to the reader
they are the same thing.

**A poster pass is still owed.**
